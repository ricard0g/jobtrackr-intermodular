# Reflexión personal - Proyecto JobTrackr

## Qué he aprendido

Este proyecto me ha enseñado a:

- Conectar contenidos de varios módulos (BBDD, Programación, Lenguajes de marcas, Entornos, Sistemas, Empleabilidad).
- Ver la relación directa entre:
  - El modelo de datos.
  - El código Java.
  - El comportamiento del frontend.
- Valorar la importancia de:
  - Una buena estructura de repositorio.
  - Un README claro.
  - Una documentación mínima pero útil.

También he reforzado:

- SQL y diseño de bases de datos relacionales.
- Uso de JDBC con Java Core.
- Desarrollo de interfaces web más modernas con React y Tailwind.

Más allá de la tecnología, he aprendido a pensar más en términos de arquitectura y responsabilidades, y no solo en conseguir que algo “funcione”.

---

## Qué se me ha dado mejor

Se me ha dado especialmente bien:

- El diseño conceptual del dominio:
  - Definir entidades (usuarios, empresas, candidaturas, estados).
  - Identificar relaciones entre ellas.
  - Traducirlo a un modelo relacional.
- Diseñar el flujo del tablero Kanban:
  - Pensar cómo se mueve una candidatura entre fases.
  - Decidir qué información necesita ver el usuario en cada momento.
- Trabajar con Git y GitHub:
  - Crear y mantener el monorepo.
  - Hacer commits frecuentes y descriptivos.
  - Mantener el proyecto ordenado.

Esto me ha dado sensación de control y claridad durante el desarrollo.

---

## Qué me ha costado más

Lo más difícil ha sido:

- Gestionar la ambición técnica:
  - Querer añadir muchas cosas (autenticación avanzada, despliegue, etc.).
  - Y a la vez cumplir con los plazos y los requisitos mínimos.
- Integrar varias capas y tecnologías:
  - Errores de consultas SQL.
  - Detalles de CORS o JSON.
  - Ajustes entre frontend y backend.

Estos retos me han recordado la importancia de probar con frecuencia y avanzar por pasos pequeños.

---

## Qué mejoraría en el futuro

Si empezara de cero, intentaría:

- Definir mejor el MVP desde el principio:
  - Qué es obligatorio entregar.
  - Qué se deja como mejora opcional.
- Dedicar más tiempo a:
  - Pequeñas pruebas automatizadas o scripts de comprobación básica, estar probando todo manualmente lleva demasiado tiempo.
  - Documentar decisiones técnicas importantes.
- Pensar antes en la escalabilidad del código:
  - Cómo afectarán futuras funcionalidades a la estructura actual.
  - Qué puedo dejar preparado desde ahora (sin sobrecomplicar).

En lo personal, este proyecto me confirma que quiero seguir en el camino del desarrollo de software y la ingeniería. También me recuerda que el crecimiento viene de combinar técnica, constancia y una buena actitud ante el error y el aprendizaje.
